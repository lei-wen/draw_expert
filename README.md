# 平局专家 · draw-expert

结合红火体育赛事数据与泊松模型，分析足球常规时间平局概率、筛选候选比赛并复盘预测的 Agent Skill。

支持单场分析和批量筛选，分别展示**模型平局概率**、**市场去水隐含概率**及两者的**百分点差值**。数据不足时说明原因，没有合适候选时不强行凑数。

> 本仓库提供技能指令、模型说明和给定参数的概率计算器。实时取数依赖另行安装的 `sports-api-skill`；计算脚本本身不调用赛事接口，也不训练模型。

## 功能

| 场景 | 输出 |
| --- | --- |
| 单场平局分析 | 赛事与时间、模型参数、胜平负概率、支持与反对证据 |
| 批量平局筛选 | 候选排名、市场概率差、数据完整度及排除原因 |
| 比分分析 | 整体比分 Top 3、平局比分 Top 3，各附无条件概率 |
| 市场对比 | 同一公司、时点及结算口径的胜平负赔率比例去水 |
| 预测复盘 | 对照实际赛果，按需评估校准、Brier 分数或对数损失 |

默认分析常规时间与伤停补时，不含加时赛、点球大战。默认时区为 `Asia/Shanghai`；“今天在售”按接口销售日与销售状态核对，开球可能在次日。

## 安装

需要能读取附带文件、运行 Python 和调用外部接口的 Agent Skills 兼容客户端。以下为本机使用的共享技能目录安装示例：

```bash
mkdir -p "$HOME/.agents/skills"
git clone https://github.com/lei-wen/draw_expert.git "$HOME/.agents/skills/draw-expert"
```

文件夹使用技能名称 `draw-expert`，仓库名称为 `draw_expert`。如目标目录已存在，先检查其内容；不要覆盖已有修改。

若客户端使用其他技能目录，将完整仓库放入其支持的目录，保留 `SKILL.md`、`agents/`、`references/` 和 `scripts/`。按客户端要求刷新技能索引或开启新会话，确认能发现 `draw-expert`。不要仅复制入口文件。

更新 Git 安装的副本：

```bash
git -C "$HOME/.agents/skills/draw-expert" pull --ff-only
```

### 数据依赖与凭据

另行安装完整的 **`sports-api-skill`**，包含路由表、接口指南及请求脚本。数据权限和服务可用性由红火体育提供方决定。本仓库不打包该依赖，也不包含凭据。

在启动 Agent 的进程环境中配置以下变量，填写自己的合作方凭据：

```bash
export SPORTS_API_APP_ID='你的合作方ID'
export SPORTS_API_APP_SECRET='你的合作方密钥'
# 可选；省略时使用数据技能的默认生产地址
export SPORTS_API_BASE_URL='https://apic.17honghuoyun.com'
```

`.env` 不会自动加载。桌面客户端需要实际继承环境变量；云端执行环境需单独配置 Secrets。只检查变量存在性，不打印值：

```bash
test -n "$SPORTS_API_APP_ID" && echo 'APP_ID 已配置'
test -n "$SPORTS_API_APP_SECRET" && echo 'APP_SECRET 已配置'
```

实时接口通常需要 Bash、curl、出站 HTTPS，以及服务商要求的出口 IP 白名单。Python 概率计算器只使用标准库，支持 Python 3.6 及以上，无需 pip 安装依赖。

在支持 `$技能名` 的客户端中：

```text
使用 $draw-expert 筛选今天在售竞彩足球中的平局候选，列出前三场；数据不足的比赛说明原因。
```

```text
使用 $draw-expert 分析比赛 ID 为【实际比赛ID】的常规时间平局概率，比较市场去水概率，并列出整体比分和平局比分各前三名。
```

```text
使用 $draw-expert 根据我提供的赛前样本和赔率分析这场比赛，注明简化估计方法与缺失信息。
```

缺少必填 ID 或查询范围时，Agent 会集中补问；不会猜测 ID。仅有球队名时，先通过赛程确认具体比赛。没有 API 凭据时仍可分析用户提供的数据。

## 数据与分析流程

1. 通过 `sports-api-skill` 路由定位比赛，按需读取战绩、排名、球队统计、阵容与市场指数。
2. 检查比赛身份、预测时点、主客场、样本日期及统计口径；区分联赛、杯赛和友谊赛。
3. 根据实际样本估计两队预期进球；足够数据时拟合球队攻防，小样本时披露简化方法及限制。
4. 计算独立泊松基线；仅在有历史拟合依据时使用双变量共享成分。
5. 比较市场概率并检查敏感性，输出候选、观察、不列入或数据不足的判断。

接口未返回的 xG、伤停和历史赔率不会被补造；历史首发不当成本场确认首发。推断仅使用预测时点之前可获得的信息。

## 本地概率计算

在仓库根目录执行：

```bash
# 独立泊松基线
python3 scripts/score_probs.py --mu 1.1 --lam 0.9 --kappa 0

# 共享成分模型，并比较主胜／平局／客胜十进制赔率
python3 scripts/score_probs.py --mu 1.1 --lam 0.9 --kappa 0.1 --odds 2.5 3.1 2.9
```

数字仅为运行示例，不是默认赛事参数或预测结果。

| 参数 | 含义与约束 |
| --- | --- |
| `--mu` | 主队边际预期进球，必填，0–30 |
| `--lam` | 客队边际预期进球，必填，0–30 |
| `--kappa` | 共享泊松成分均值，默认 0，范围 0 到 min(μ, λ) |
| `--odds` | 可选，依次为主胜、平局、客胜赔率；均为有限数且大于 1 |

输出 JSON 包含模型参数、胜平负概率、比分排名和截断遗漏概率。提供赔率时还返回市场比例去水概率及平局概率差。

- 概率以 **0–1** 表示，报告时乘 100 转为百分比。
- `draw_gap_percentage_points` 已是**百分点**，无需再乘 100。
- `top_draw_scores` 为每个平局比分的无条件概率，不是“已知平局后的比分概率”。
- 脚本自适应扩大比分矩阵，以边际尾部概率和小于 `1e-9` 作为截断条件。

### 模型口径

共享成分模型令 `X=A+C`、`Y=B+C`，三个成分相互独立，均值分别为 `μ−κ`、`λ−κ`、`κ`。因此两队边际预期进球仍为 `μ`、`λ`，协方差为 `κ`。

κ 为 0 时退化为独立泊松。κ 需由历史数据估计，不默认固定相关系数为 0.2。完整模型说明、约束与文献见 [references/model.md](references/model.md)。

市场对比采用比例去水：`q_i=(1/o_i)/Σ(1/o_j)`。正概率差只表示模型高于该市场基准，不足以证明真实优势或收益。

## 报告结构与限制

批量报告的核心字段：

| 比赛 | 开赛时间 | 模型平局概率 | 市场平局概率 | 概率差 | 数据完整度 | 判断 |
| --- | --- | --- | --- | --- | --- | --- |
| 实际查询后填充 | 注明时区 | 实际计算 | 同口径去水 | 百分点 | 缺失项 | 候选／观察／排除 |

没有数据时不会填入虚构数字。未取得足够联赛样本时，不能声称完成攻防强度、对手强度及主场优势校准；没有历史验证就不能宣称准确率或收益表现。模型与市场明显冲突时需排查原因，不能仅按正差值机械推荐。预测不保证赛果或收益。
